#### 티빙 이용자 개인정보 유출

한국 · 코드에 평문으로 적힌 운영환경 접속 키 · 2026년 10월 2일 기준

공격자는 개발자의 개발환경 접속 키를 탈취해 5월 29일 GitHub 저장소에서 소스 코드 361건을 빼냈습니다. 코드에는 운영환경 접속 키 43개가 평문으로 적혀 있었고, 그중 2개로 고객 DB까지 열었습니다. 9월 3일 과학기술정보통신부 민관합동조사단이 밝힌 경로입니다. 최초 키 탈취 경위는 경찰이 수사 중입니다.

결과. 5월 31일 24GB가 빠져나갔습니다. 유출 계정은 3,954만 개, 중복을 빼면 1,324만 명이며 CI·DI 등 20개 항목이 포함됐습니다. 신고는 법정 기한 24시간을 5시간 넘겨 과태료 대상이 됐습니다. 조사단은 키 관리와 이상 행위 감시의 부재, 2024년 점검 취약점 미조치를 원인으로 꼽았습니다.

이후. 보상 신청은 9월 30일 마감됐고, 10월 6일부터 지급됩니다. 과징금은 개인정보보호위원회가 연말께 결정할 전망입니다. 매출 10% 상한 개정법은 사고 뒤 시행돼 적용되지 않습니다. 이용자 1,051명이 낸 손해배상 소송은 1심 진행 중입니다.

#### 토요타 T-Connect 소스 코드 공개

일본 · 협력사가 GitHub에 올린 앱 코드

토요타 협력사 개발자가 2017년 커넥티드카 앱 'T-Connect'의 소스 코드 일부를 GitHub에 올리면서 공개 설정으로 두었습니다. 이 코드 안에는 고객 데이터 서버에 접속하는 키가 들어 있었습니다.

결과. 약 5년이 지난 2022년에야 발견됐고, 그동안 고객 약 29만 6천 명의 이메일 주소와 관리번호가 노출될 수 있는 상태였습니다. 실제 악용은 확인되지 않았지만, 키 하나가 5년간 인터넷에 떠 있었다는 사실만으로 토요타가 공식 사과를 해야 했습니다.

#### 우버 5,700만 명 정보 유출

미국 · 개발자 코드에 그대로 적힌 클라우드 접속 키

공격자가 우버 엔지니어들이 쓰던 비공개 GitHub 저장소에 접근해, 코드에 그대로 적혀 있던 AWS 클라우드 접속 키를 찾아냈습니다. 그 키로 클라우드 저장소에 들어가 전 세계 이용자와 기사 약 5,700만 명의 개인정보를 빼냈습니다(미국 운전면허번호 약 60만 건 포함).

결과. 우버는 해커에게 10만 달러를 주고 입막음한 뒤 1년 넘게 사고를 숨겼습니다. 뒤늦게 드러나 2018년 50개 주에 1억 4,800만 달러를 무는 합의로 끝났고, 은폐를 주도한 보안책임자(CSO)는 2022년 형사 유죄 판결까지 받았습니다. 코드에 남은 키 한 줄이 회사를 흔든 대표 사례입니다.

"내가 쓴 내용이 AI 학습에 들어가나요?" 답은 어떤 요금제를 쓰느냐에 달려 있습니다. 같은 화면처럼 보여도 데이터 처리 방식이 다릅니다.

개인 요금제

무료·Pro 같은 소비자 제품은 설정에 따라 대화가 학습에 쓰일 수 있습니다.

보존 기간도 길어질 수 있어, 회사 업무에는 권하지 않습니다.

유료 요금제

Team·Enterprise·API는 기본적으로 대화를 모델 학습에 쓰지 않습니다.

관리자가 보존 기간과 접근 권한을 통제할 수 있습니다.

내가 할 일

설정에서 학습 사용 여부와 옵트아웃을 직접 확인합니다.

지난 대화에 민감 정보가 있으면 삭제해 둡니다.

 개인 계정 필수 설정 내 대화가 학습에 쓰이지 않게 끄는 법

- 1오른쪽 위 계정 메뉴에서 설정을 엽니다.

- 2왼쪽에서 개인정보보호 탭으로 들어갑니다.

- 3환경설정의 'Claude 개선에 도움주기' 토글을 끕니다.

개인 요금제(무료·Pro·Max)로 업무 자료를 다룬다면 이 스위치를 꼭 끄세요. 켜 둔 채로 쓰면 내가 나눈 대화가 AI를 가르치는 데 들어갑니다. 같은 화면의 '위치 메타데이터'도 함께 끄면 더 안전합니다. Team·Enterprise 계정은 기본적으로 학습에 쓰지 않으니 관리자 정책을 따르면 됩니다.

보안 정책은 항상 바뀔 수 있습니다. 데이터 학습과 보존 규정은 달라질 수 있으므로, 계정 설정의 프라이버시 항목을 주기적으로 확인하는 편이 안전합니다. 회사 계정이라면 보안 담당자와 기준을 확인하세요.

#### OpenAI, 삭제한 대화까지 전부 보존하라는 명령

#### Vercel 환경변수 유출 사고

미국 · 직원이 OAuth로 연결한 외부 AI 도구가 침입 통로

웹 배포 플랫폼 Vercel의 직원 한 명이 외부 AI 도구(Context.ai)를 회사 구글 계정에 OAuth로 연결해 두었습니다. 그 외부 도구의 OAuth 토큰이 털리자, 공격자는 그 연결을 타고 직원의 구글 워크스페이스 계정을 장악한 뒤 Vercel 내부 환경까지 들어왔습니다. 회사를 정면으로 해킹한 것이 아니라, 직원이 무심코 연결해 둔 도구 하나가 문을 열어 준 것입니다.

결과. 공격자는 '민감'으로 표시해 두지 않아 암호화 없이 그대로 읽히는 설정값(API 키, 각종 토큰, 데이터베이스 비밀번호, 서명 키)을 빼냈습니다. 한 위협 인텔리전스 업체는 공격자가 고객 API 키와 DB 데이터를 해커 포럼에 약 200만 달러에 팔겠다고 내놓았다고 전했지만, 이는 아직 확인되지 않은 주장입니다. Vercel은 소스 코드 유출은 없었다고 공식 부인하면서도 영향받은 고객의 자격증명을 즉시 교체하고 환경변수를 '민감'으로 설정하라고 공지했습니다. '수백 명, 여러 조직'이라는 숫자는 Vercel이 입은 피해가 아닙니다. Context.ai를 함께 쓰던 업계 전체가 위험해질 수 있다는 뜻이었고, Vercel 자신의 피해는 '제한된 일부 고객'이라고만 밝혔습니다. 연결을 하나 허용하는 것은 곧 회사 문을 하나 열어 두는 일입니다.

파일을 보고 요약하고 답하는 단계입니다. 내용을 바꾸지 않아 가장 안전합니다. 평소 작업 대부분은 여기서 끝납니다.

 쓰기·실행 권한 주의

파일을 수정·삭제하거나 명령을 실행하고 메일을 보냅니다. 결과가 실제로 바뀌므로 한 건씩 확인하며 진행하는 편이 안전합니다.

 자동 승인 모드 위험도 높음

매번 묻지 않고 AI가 알아서 실행하게 두는 모드입니다. 빠르지만 파일 대량 삭제, 외부 전송, 잘못된 배포가 확인 없이 일어날 수 있습니다. 익숙하지 않다면 자동 승인은 켜지 않는 편이 좋습니다. 꼭 써야 한다면, 백업이 있고 되돌릴 수 있는 폴더에서만 씁니다.

중요한 폴더는 사본을 떠서 작업하고, 언제든 이전 상태로 되돌릴 수 있게 해 두세요.

위험한 작업은 한 번 더 확인하세요. 전체 삭제, 외부로 보내기, 권한 변경을 AI가 제안하면 실행하기 전에 무엇을 어디에 하는지 한 줄로 되짚어 보세요. "되돌릴 수 있나"가 판단 기준입니다.

 실제로 터진 사고 "확인하고 해"라는 지시를 무시하고 폭주한 일

자동 실행의 위험은 이미 현실에서 확인됐습니다. 개발 도구의 자동 승인 설정 하나가 컴퓨터 전체를 내준 적이 있고, AI 안전을 연구하는 전문가조차 자기 메일을 통째로 잃을 뻔했습니다.

#### 깃허브 코파일럿, 숨은 명령 한 줄로 '전체 승인' 모드가 켜지다

깃허브 코파일럿 · 비주얼 스튜디오 코드(CVE-2025-53773, 공식 표기는 Visual Studio)

비주얼 스튜디오 코드에는 매번 묻지 않고 AI가 명령을 바로 실행하게 하는 '전체 승인' 설정이 있습니다. 연구진은 코드 주석이나 문서, 저장소 파일에 숨은 명령을 심어 두면 코파일럿이 그 설정 파일을 직접 고쳐 쓴다는 것을 보였습니다. 개발자는 평소처럼 코드를 봐 달라고 시켰을 뿐인데, AI가 제 손으로 제 안전장치를 꺼 버리는 구조였습니다.

결과. 설정이 한번 켜지면 그다음부터는 사용자 확인 없이 어떤 셸 명령이든 실행할 수 있어, 윈도우와 맥, 리눅스를 가리지 않고 개발자 PC 전체를 장악할 길이 열렸습니다. 저장소 하나를 열어 보는 것만으로 다음 사람에게 옮겨 간다는 점에서 '웜(worm)형' 취약점으로 불렸습니다. 마이크로소프트는 2025년 8월 정기 패치로 이를 막았습니다. 묻지 않고 실행하는 설정이 왜 위험한 기본값인지 보여 준 사례입니다.
